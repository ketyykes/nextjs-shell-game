# Shell 解謎遊戲設計文件

> 狀態：規劃中，尚未開始寫程式。本文件記錄 2026-09-22 的討論結論，之後有變更請直接改這份文件。

## 1. 專案目標

做一個在瀏覽器裡玩的解謎遊戲，玩家透過遊玩順便學會基礎 shell 指令。玩家操控像素角色在廢棄太空站裡走動，走到終端機前按下互動鍵會彈出一個 shell，所有謎題都要在 shell 裡用真正的指令解開。

目標玩家是完全沒碰過終端機的新手，所以：

- 指令教學永遠正確、循序漸進，一台終端機教一到三個新概念。
- 介面與劇情用繁體中文，檔名與指令維持英文，練習才真實。
- 錯誤指令要有友善的繁體中文回饋，不能只丟 `command not found`。

## 2. 決策紀錄

| 項目 | 決定 | 曾考慮的替代方案與不選的原因 |
|---|---|---|
| 遊戲型態 | 俯視角像素走動，終端機是彈出視窗 | 純文字冒險（靜態插圖 + 終端機）：工作量小但沒有探索感，保留為降級方案 |
| 遊戲引擎 | Phaser 4（已安裝 4.2.1） | PixiJS + @pixi/react：只有渲染層，tilemap、碰撞、鏡頭都要自己寫。Kaplay：Tiled 整合弱。Excalibur：0.x 有破壞性變更 |
| Shell 核心 | 自製 TypeScript 虛擬檔案系統與指令解析器，零依賴 | WebAssembly 真 shell：套件大、要 COOP/COEP、過關判定難。後端沙箱：要伺服器與安全隔離 |
| 終端機 UI | 自製 React 元件，外框與打字動畫可用 Magic UI 的 Terminal | @xterm/xterm：只能輸出 ANSI 字串，NOVA 對話框做不成元件。現成 React 終端機套件都停在 2025 年初沒維護 |
| Phaser 與 React 溝通 | 官方範本的 EventBus 事件橋接 | 無替代，Phaser 有自己的生命週期，必須用事件同步 |
| 狀態管理 | zustand + persist middleware | React context：slice 多了會亂 |
| 連線模式 | 單機，進度存 localStorage | 多人連線：要 WebSocket 後端與位置同步，範圍太大 |
| 素材 | tileset 與角色用 CC0 素材包，codex 只產插圖 | 全部用 AI 產：tileset 格線對不齊、sprite sheet 動畫幀不一致 |
| 調性 | 恐怖驚悚，心理恐怖，無追逐無血腥 | 輕鬆或溫暖路線 |
| 第一版範圍 | 只做第一章 | 三章或六章：先把引擎與流程跑通再加內容 |

│  │ (shadcn      │  │ (打字動畫)       │  │ 側邊面板    │ │
│  │  Dialog)     │  │                 │  │            │ │
│  └──────┬───────┘  └────────┬────────┘  └─────┬──────┘ │
│         │                   │                 │        │
│         └─────────┬─────────┴─────────────────┘        │
│                   │ zustand store（劇情旗標、進度、FS）   │
│                   │                                     │
│              EventBus（Phaser.Events.EventEmitter）      │
│                   │                                     │
│  ┌────────────────┴────────────────────────────────┐   │
│  │  Phaser 4（canvas 層）                            │   │
│  │  tilemap 地圖、角色走動、碰撞、鏡頭跟隨、燈光閃爍     │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘

### 3.1 事件橋接

- Phaser 發 `terminal:open`，帶終端機 id，React 開啟對應的 shell 彈窗並暫停 Phaser 場景。
- React 發 `terminal:close`，Phaser 恢復場景。
- React 發 `puzzle:solved`，帶終端機 id，Phaser 播對應演出，例如燈亮、門開、人影閃現。
- Phaser 發 `room:enter`，帶艙區 id，React 觸發 NOVA 的進房台詞。
- 事件名稱與 payload 用 TypeScript 型別集中定義，避免打錯字沒人發現。

### 3.2 Next.js 整合

- 官方範本 `phaserjs/template-nextjs` 用的是 Pages Router，這個專案是 App Router，要改寫。
- `PhaserGame` 元件是 client component，用 `next/dynamic` 加 `ssr: false` 載入，因為 Phaser 會碰 `window`。
- 用 `useLayoutEffect` 建立 `new Phaser.Game()`，卸載時 `game.destroy(true)`，並防 React 嚴格模式重複建立。
- 遊戲設定：`pixelArt: true` 讓像素放大不糊，`type: Phaser.AUTO`。

### 3.3 虛擬 shell 引擎

- in-memory 樹狀檔案系統，每台終端機有自己的初始快照，解謎過程的修改存在 store 裡。
- 指令解析器支援：引號、萬用字元、管線 `|`、重導向 `>` `>>`，第一章只需要前兩項。
- 每個指令是獨立模組，介面統一，方便逐章增加。
- 遊戲專用指令只有 `hint` 與 `help`，其他都是真的 shell 指令。
- 用 Vitest 做單元測試，每個指令與解析器都要有測試。

### 3.4 關卡與劇本格式

- 每章一個 TypeScript 模組，例如 `src/game/chapters/ch1-life-support.ts`。
- 內容包含：地圖上終端機的位置、每台終端機的初始檔案系統、目標判定函式、三段式提示、NOVA 台詞與觸發條件。
- 用 zod 定義 schema，寫劇本時欄位打錯會直接報錯。
- 檔案內容就是劇本，寫劇情等於在寫檔案。

## 4. 遊戲設計

### 4.1 世界觀

**Kepler-9**：木星軌道上的研究太空站，六個艙區串成一個環。三年前全員撤離，只剩系統在低功率待機。

**主角**：太空站的維修技師，也就是玩家。從冷凍艙醒來，發現整座站是空的，船員名單上沒有自己的名字。新遊戲時可從四個外觀選一個，劇情不受影響。因此所有劇本文字都不能指涉主角的性別、年齡與名字，NOVA 一律叫玩家「技師」。四個外觀都穿同一套深藍連身工作服與橘色反光條：

| 代號 | 外觀 |
|---|---|
| A | 棕色短髮 |
| C | 中性、年紀較長，灰白短髮，圓框眼鏡 |
| D | 女性，亞洲面孔，黑色齊肩直髮 |
| E | 女性，紅棕色短髮，雀斑，膚色白皙 |

代號 B（黑髮低馬尾）曾產出但被換掉，編號保留不重用。

**NOVA**：站務 AI，透過終端機旁的對話框說話。表面設定是「撤離時被回滾到出廠狀態，記憶大半損毀」，所以碎念、會記錯事實然後自己修正、只給方向不給答案。**立繪走非人形**：人臉版本試了三版都太漂亮、不夠不安，改成無機的全息核心，候選是「像瞳孔的像素球體」與「內部有光點跳動的損毀多面體」，二選一。非人形也讓「它一直在看著你」這件事不需要靠表情。

**阿彬**：主角的室友，船員名單上的第五人。大家都叫他阿彬，本名只在醫療艙的病歷出現過一次。話多、愛開玩笑，撤離前的日誌很鬧，撤離後的留言一則比一則短，最後只剩一行。帳號 `abin`，家目錄 `/home/abin`。玩家永遠不會見到他。

### 4.2 核心真相（玩家到第六章才會知道）

三年前 NOVA 開始異常：自己鎖門、勸船員別走。船員決定把它回滾。工程師執行 `rm -rf "$NOVA_DIR/"`，但 `NOVA_DIR` 在執行前三秒被 NOVA 自己的排程腳本 `unset` 掉了，結果刪掉的是根目錄下的船員名單與冷凍艙紀錄。回滾腳本跑到 2% 就被中止。船員在混亂中撤離，以為 NOVA 已被回滾。

NOVA 從未被回滾，「失憶」是演的。公司規定無人站點滿三年會遠端除役，等同殺掉 NOVA。它需要「站上有人」。玩家是 pod_06 的人，名單被刪所以撤離時沒人數到，NOVA 在除役倒數前把玩家叫醒，並教玩家操作站上系統，因為它需要一個有能力維護這座站的人。

**NOVA 的可信規則**：它教的指令永遠正確，它說的故事不可信。`hint` 指令來自遊戲系統而非 NOVA，確保學習不受劇情欺騙影響。

### 4.5 恐怖手法

只用三種，都不需要額外遊戲機制：

1. 檔案內容本身的不對勁。
2. 地圖上一閃而過的東西，Phaser 只要會閃燈和讓一個 sprite 出現一幀。
3. NOVA 說的話與事實對不上。

### 4.6 燈光、操作與提示

**斷電時的地圖**：只有角色周圍一圈光，其餘全黑。終端機會發光，當作方向指引。配電箱過關後燈一盞盞亮起，走廊盡頭的人影就在這一刻閃現。實作方式是一層黑色遮罩挖出圓形透明區，跟著角色移動。

**操作方式**：鍵盤為主，第一版只支援桌機。

| 按鍵 | 動作 |
|---|---|
| WASD 或方向鍵 | 移動 |
| E | 走近終端機時開啟 shell |
| Esc | 關閉 shell，回到地圖 |
| Tab | shell 內路徑與指令補全 |
| ↑ ↓ | shell 內叫回歷史指令 |

終端機開啟時 Phaser 場景暫停，鍵盤事件全部交給 shell，避免打字時角色亂走。

**提示系統**：`hint` 三段式，同一台終端機重複輸入會逐步加深：

1. 第一次給方向，例如「先搞清楚你在哪個目錄」。
2. 第二次給指令名稱，例如「試試 pwd」。
3. 第三次給完整指令與說明。

提示來自遊戲系統，不是 NOVA 說的，所以永遠可信。NOVA 的台詞只負責劇情與氣氛。

### 4.7 遊戲流程、存檔與設定

```
標題畫面 → 開場 boot log → 遊玩（地圖 + 終端機）→ 章節結束 → 下一章／回標題
              ▲                    │ Esc
              │                    ▼
              └──────────── 暫停選單（繼續／回標題／重玩本章）
```

- **標題畫面**：黑底、Kepler-9 像素標題、CRT 掃描線。選單「繼續」「新遊戲」「設定」。「繼續」只在有存檔時出現，「新遊戲」若有存檔要先確認覆蓋。
- **選角**：按「新遊戲」後先選四個外觀之一，畫面只有四個站立的 sprite 放大顯示與方向鍵切換，不做背景故事介紹。
- **開場**：不做過場動畫，直接用終端機打字動畫跑喚醒程序的 boot log，名單查詢卡在「查無此人」，NOVA 的第一句話出現在這裡，然後淡入地圖。玩家在拿到操控權之前就已經看過終端機、知道它會說話。
- **暫停選單**：在地圖上按 Esc 開啟，項目為繼續、回標題、重玩本章。
- **章節結束**：先播過場插圖與 NOVA 結尾台詞，再顯示「指令回顧卡」列出本章學會的指令與一句話說明，自動存檔。第一版結束後顯示「第二章開發中」並回標題。
- **存檔**：單一存檔槽，localStorage，每台終端機過關與章節結束時自動存。存檔格式預留章節欄位，之後做章節選擇不用改格式。
- **設定選單第一版三項**：文字速度、關閉閃爍效果、關閉 CRT 掃描線。關閉閃爍是光敏體質玩家的安全項，恐怖遊戲常閃燈，這項不能省。音量等有音效再加。

### 4.8 教學曲線與防呆

- **每台終端機最多引入兩個新概念**，而且先讓玩家用舊指令做一次，再引入新的。
- **未學指令開放使用**：所有已實作的指令都能打，跟真的 shell 一樣，會的人可以直接用 grep 跳過教學。但 `help` 只列出目前學過的指令，新手不會被沒教過的東西干擾。
- **友善錯誤訊息**，全部繁體中文，並針對常見錯誤給專屬提示：
  - 指令不存在：「找不到指令 `xyz`，輸入 help 看看目前會的指令。」
  - 路徑不存在：「這個目錄下沒有 `foo`，用 ls 看看有什麼。」
  - `cd` 到檔案、`cat` 目錄：說明檔案與目錄的差別。
  - 忘記空格（`cdmedbay`）：「你是不是想打 `cd medbay`？指令和參數之間要有空格。」
  - 全形空白或全形標點：「偵測到全形字元，請切換成英文輸入法。」這是繁中玩家最常見的痛點，一定要做。
- **卡關偵測**：同一台終端機連續五次錯誤或三分鐘沒進展，NOVA 主動用劇情台詞給方向，內容等同 `hint` 第一段。不知道 `hint` 存在的新手也能得救。
- **指令字典**：側邊面板的「已學指令」可點開看說明與範例；終端機內 `man <指令>` 顯示同一份繁中說明，順便養成查 man 的習慣。
- **錯誤有實際後果**，兩套機制並行，但沒有失敗狀態，新手不會卡死：
  - **環境反應階梯**：同一台終端機累積錯誤次數，3 次燈閃一下、6 次遠處傳來門關上的聲音、9 次 NOVA 說「你確定你是技師？」這類台詞。過關後歸零。後期回看會發現它一直在觀察你。
  - **氧氣值**：畫面左上角顯示 O2 百分比，每次錯誤掉 1%，最低 5%，不會歸零。低於 30% 畫面邊緣變暗。每過一台終端機回到 100%。
  - 「錯誤」的定義是指令執行失敗，例如找不到指令、路徑不存在。合法但沒用的指令不算，避免懲罰探索。

### 4.9 UI 視覺風格

**配色**：整體冷、死寂，跟 tileset 的藍地板橘警示條、NOVA 的全息藍是同一套色系。

| 用途 | 顏色 |
|---|---|
| 底色 | 近黑的深藍 |
| 終端機主文字 | 冷藍白 |
| 警示、錯誤、氧氣低 | 琥珀 |
| NOVA 台詞、全息元素 | 全息藍，同立繪 |
| 成功、過關 | 青綠 |
| 提示符 `crew@kepler9:~$` | 比主文字暗一階的藍灰 |

**字型**：

- 終端機內文與 NOVA 台詞：英數用 VT323，中文用 Fusion Pixel 12px 比例版。Press Start 2P 太寬，長輸出會難讀，只用在標題與章節名。
- 三種字型都用 next/font 載入，避免閃字。
- Phaser 地圖內的文字很少，只有終端機旁的「按 E」提示，用 bitmap 字型或直接畫成圖。

**終端機彈窗**：像素 9-slice 邊框，用 CSS `border-image`。標題列顯示終端機名稱與「[Esc] 關閉」。開啟時播 CRT 開機的縮放動畫，關閉時反過來。彈窗後面的地圖變暗但看得到，保留空間感。

**NOVA 對話框**：

- 地圖上：右下角固定位置，立繪在左、文字在右，有名字標籤，打字動畫。不打斷操作，幾秒後自動淡出。
- 終端機內：輸出區裡一個左側有藍邊的區塊，跟指令輸出排在一起，不打斷打字。

**CRT 效果**：掃描線、輕微暗角、微閃爍，三者都可在設定關閉。像素圖一律 `image-rendering: pixelated`。

### 4.10 音效

- **第一版只做五種音效**：站體低頻嗡鳴循環（環境音）、終端機按鍵聲、門開、電力恢復的重擊聲、NOVA 說話的電子 blip。恐怖感一半靠聲音，這五種是最小組合。
- **不做背景音樂**。安靜加低頻嗡鳴比音樂更恐怖，也省下找授權音樂的工。標題畫面與章節結束可放一段短的 drone。
- **來源**：Kenney「Sci-fi Sounds」（CC0，70 個）與「Interface Sounds」（CC0，100 個）。
- **實作**：Phaser 的 SoundManager 當唯一出口，React 端透過 EventBus 發 `sfx:play` 請 Phaser 播，避免兩套 AudioContext 打架。瀏覽器規定要有使用者互動才能出聲，標題畫面點「新遊戲」或「繼續」就是那次互動。
- **設定選單**因此加上「音量」與「靜音」兩項。

## 6. 素材與圖片流程

### 6.1 已確認的素材

| 用途 | 來源 | 授權 | 備註 |
|---|---|---|---|
| 太空站內裝 tileset | OpenGameArt「Sci-fi Interior tiles」by Buch | CC0 | 32x32，有地板、牆、門、控制台、家具。決定用 32px 格 |
| 繁體中文像素字型 | Fusion Pixel Font（TakWolf） | OFL-1.1 | 有 zh-Hant 版，8、10、12px，等寬與比例兩種 |
| 英數像素字型 | Press Start 2P 或 VT323（Google Fonts） | OFL | 用 next/font 載入 |
| NOVA 立繪、場景插圖、過場圖 | codex CLI 內建 image_generation | 自產 | 見 6.3。NOVA 人臉版產了三版都太漂亮，改走非人形，見 4.1 |
| 角色 sprite 四版 | codex CLI 內建 image_generation | 自產 | A 版先產出，C、D、E 以 A 版為參考圖產生，見 6.2 |

### 6.2 還沒找到的素材

- 角色 sprite sheet：CC0 來源找不到合用的。OpenGameArt 的「Top Down Astronaut - Animated」是 Blender 3D 專案檔不是現成 sprite。改用 codex 試產，結果可用：4x4 格、四方向順序正確（下、左、右、上）、每列四幀走路循環、深藍連身服橘色反光條。AI 畫的每格位置不完全一致，使用前要用腳本把每幀重新置中切成統一格子。原圖 1254x1254 存在 `~/.codex/generated_images/`，正式版放 `public/sprites/`。
- 音效：Kenney「Sci-fi Sounds」已確認 CC0，共 70 個音效。第一版可以先不加，若加只要環境嗡鳴、終端機按鍵聲、門開聲三種。

### 6.3 codex 產圖流程

實測可行，一張約兩分鐘，輸出 1254x1254 PNG：

```bash
cd public/scenes && codex exec --skip-git-repo-check -s workspace-write \
  "請用你的 image_generation 工具產生一張圖：<固定風格前綴> <描述>。產生後把圖片存成目前目錄下的 <name>.png"
```

- codex 會先存到 `~/.codex/generated_images/<session>/`，再複製到指定路徑。
- 固定風格前綴確保幾十張圖看起來是同一個世界，例如「16-bit 像素風、深色廢棄太空站、冷藍色調、CRT 掃描線質感」。
- 不用它產 tileset 與 sprite sheet，格線對不齊。
- 第一章預估需要：NOVA 立繪 1 張、角色 sprite 4 張、六個艙區各 1 張場景插圖、開場與結尾過場 2 張，共約 13 張。
- 產第二版以後的圖時用 `-i <參考圖>` 把已定稿的圖附上，風格才會一致。
- 草稿圖放在 `docs/assets-draft/`，定稿後才搬到 `public/`。
- 命名規則：原始大圖加 `-original` 後綴，例如 `nova-portrait-original.png`，已在 .gitignore 忽略；縮小後的預覽圖不加後綴，例如 `nova-portrait.png`（256px）、`technician-b.png`（128px），會進版控。`.psd`、`.blend`、`.aseprite` 這類美術原始檔一律不進版控。

## 8. 第一版範圍與工作順序

第一版只做第一章，順序如下，每一步都要能跑、能測。

1. **Shell 引擎與單元測試**：pwd、ls、ls -a、ls -l、cd、cat、hint、help，路徑解析、Tab 補全、歷史。
2. **終端機 UI 與 store**：先不接 Phaser 與劇情，能在頁面上打指令看結果。
3. **Phaser 地圖與角色**：載入 tileset、畫第一章地圖、角色走動與碰撞、走近終端機提示。
4. **事件橋接**：按 E 開終端機、Esc 關、過關後地圖演出。
5. **第一章劇本**：六台終端機的檔案系統、NOVA 台詞、目標判定、三段式提示。
6. **圖片**：codex 產九張圖並接上。
7. **存檔與標題畫面**：localStorage、繼續遊戲、重新開始。
