## 1. 專案目標

做一個在瀏覽器裡玩的解謎遊戲，玩家透過遊玩順便學會基礎 shell 指令。玩家操控像素角色在廢棄太空站裡走動，走到終端機前按下互動鍵會彈出一個 shell，所有謎題都要在 shell 裡用真正的指令解開。

目標玩家是完全沒碰過終端機的新手，所以：

- 指令教學永遠正確、循序漸進，一台終端機教一到三個新概念。
- 介面與劇情用繁體中文，檔名與指令維持英文，練習才真實。
- 錯誤指令要有友善的繁體中文回饋，不能只丟 `command not found`。

### 3.1 事件橋接

- Phaser 發 `terminal:open`，帶終端機 id，並自己暫停場景（`TerminalZone` 呼叫 `scene.pause()`）；React 開啟對應的 shell 彈窗。
- React 發 `terminal:close`，Phaser 恢復場景。
- React 發 `puzzle:solved`，帶終端機 id，Phaser 依劇本宣告的過關演出（`SolvedEffect`：亮燈、開門、人影、燈閃、斷電）播放，終端機開著時延到關閉才播。
- Phaser 發 `room:enter`，帶艙區 id，React 觸發 NOVA 的進房台詞。
- 以上是主要流程。其他事件（`terminal:nearby`、`scene:ready`、`sfx:play`、`ambient:flicker`、`audio:settings`、`effects:settings`、`game:pause`／`game:resume`、`player:stopped`、`assets:error`）見 `src/game/phaser/events.ts` 的 `GameEventMap`。
- 事件名稱與 payload 用 TypeScript 型別集中定義在 `events.ts`，避免打錯字沒人發現。

### 3.2 Next.js 整合

- 官方範本 `phaserjs/template-nextjs` 用的是 Pages Router，這個專案是 App Router，要改寫。
- `PhaserGame` 元件是 client component，用 `next/dynamic` 加 `ssr: false` 載入，因為 Phaser 會碰 `window`。
- 用 `useLayoutEffect` 排一個 `requestAnimationFrame`，下一幀才呼叫 `startGame`（`main.ts` 裡 `new Phaser.Game()`）；卸載時取消排程並 `game.destroy(true)`。延後一幀是防 React 嚴格模式的 mount → unmount → mount：第一次的 cleanup 在同一幀內就取消排程，第一個遊戲不會建出來，也不會殘留兩層 canvas。`character` 或 `chapter` 變動時先銷毀再重建。
- 遊戲設定：`pixelArt: true` 讓像素放大不糊，`type: Phaser.AUTO`。
- 預取：標題流程（`usePlayPrefetch`）在標題淡入動畫跑完後的閒置時段 `router.prefetch("/play")`，並動態 import `PhaserGame` 模組（`preloadPhaserGame`，跟 `PhaserGameDynamic` 同一個 chunk），所以 **`PhaserGame` 的整個模組圖會在標題頁評估**，那條 import 鏈上不要放有副作用或依賴 `/play` 狀態的頂層程式碼。引擎排完接著預載要進的那一章插圖；進 `/play` 掛載時（`useScenePreload`）也會排本章插圖，兩邊共用同一條一次一張、低優先的 `Image` 佇列（`lib/preload.ts`），載過的留在記憶體快取，插圖卡顯示時不再發請求。
- 只用 arcade 物理，打包時用 `next.config.ts` 的 `turbopack.resolveAlias` 把 `phaser` 換成不含 Matter.js 的 `phaser-arcade-physics` 建置（M12-3）。
- 素材載入失敗：React 的 error boundary 接不到 Phaser 遊戲迴圈裡的例外，所以由 Preloader 檢查（`loaderror` 加上關鍵素材是否進了 cache），經 EventBus 的 `assets:error` 通知 React。地圖、tileset、角色 sprite 缺了就不進 Station，整個畫面顯示繁中提示與「重新載入」；只有音效缺了遊戲照常，頂端一條可收起的提示（M12-6）。

### 3.3 虛擬 shell 引擎

- in-memory 樹狀檔案系統，每台終端機有自己的初始快照，解謎過程的修改存在 store 裡。
- 指令解析器支援：引號、反斜線跳脫（`cd my\ dir`）、萬用字元、變數 `$NAME`／`${NAME}`、管線 `|`、重導向 `>` `>>`、用 `;` 與 `&&` 把一行串成好幾段、word 開頭的 `~` 與 `~/` 展開成家目錄，第一章只需要引號與萬用字元。
  - `;` 不管前一段成敗都執行下一段，`&&` 前一段成功（結束碼 0）才執行；`grep` 沒符合、`diff` 有差異、`which` 找不到雖然不算錯誤、不扣氧，結束碼照 bash 是 1，`&&` 照樣跳過右邊（`grep X f && echo 找到了` 不會印），管線的結束碼取最後一個指令；兩者都比 `|` 鬆，每一段各自是一條可以帶重導向的管線（`cat a | sort > b && cat b`）。跟 bash 一樣先解析整行，任一段有語法錯誤就一段都不執行；變數與萬用字元執行到那一段才展開，所以 `export X=/deck1; cd $X` 拿得到新值。
  - 一行串了好幾段時，任一段失敗整行算一次錯誤（扣一次氧氣、環境反應階梯加一），這一行不判定過關；全部成功時目標判定逐段看，任一段成立就過關，每一段用自己的輸出與執行完當下的工作目錄、變數、程序清單判定。
  - `~使用者`（`~abin`）不支援，原樣當成名字（等同 bash 遇到不存在的帳號）；引號內、跳脫過的、不在 word 開頭的 `~` 不展開。
- 不支援的語法不默默誤解，回「這個遊戲的 shell 不支援 X」並給替代寫法：`||`（分兩行打）、背景執行 `&`（拿掉就好）、輸入重導向 `<`、`<<`（檔名當參數或 `cat 檔名 |`）、指定檔案描述元的重導向 `2>`、`2>>`、`2>&1`、`1>`、`&>`、`>&2`、`|&`（錯誤訊息直接印在畫面上）、指令替換 `$( )` 與反引號（先單獨執行裡面的指令）。這些符號在單引號內與反斜線跳脫後是字面值，雙引號內除了 `$( )` 與反引號（bash 在雙引號內會執行它們）也是字面值。`cd` 給兩個以上參數照 bash 報參數太多。
- 每個指令是獨立模組，介面統一，方便逐章增加。
- 遊戲專用指令只有 `hint` 與 `help`，其他都是真的 shell 指令。
- 劇本之外開放使用的指令（M13-3）：`less`、`tree`、`cut`、`diff`、`which`。不編進任何章節、不在 `teaches` 裡，所以 `help` 不列，`man` 查得到，Tab 補得到。
  - `less`：真的分頁器，不是「cat 加 --More--」。shell 回傳分頁請求（`ShellExecution.pagers`），終端機把輸出區與輸入列整塊藏起來，改顯示全螢幕分頁：空白／f／PageDown 下一頁、b／PageUp 上一頁、↓ j Enter 與 ↑ k 一行、d u 半頁、g G 頭尾、`/`、`?` 搜尋（寫法同 `grep -E`，所有符合的片段標亮；狀態列換成真的輸入框，接得到中文輸入法與貼上，Enter 送出、Esc 只取消搜尋不離開分頁）與 n N、多個檔案用 `:n` `:p`。底部狀態列照 `less -M` 顯示檔名、行數範圍、百分比或 `(END)`，右邊附新手按鍵提示。q 或 Esc 只離開分頁、不關終端機；離開後畫面停在原本的提示列，分頁內容不進輸出區也不存檔，但看輸出的過關判定看得到（`grep LOCK x | less` 跟 `grep LOCK x` 一樣過關）。只有在管線最後、沒有重導向時才分頁，`less x | wc -l`、`less x > y` 照真的 less 直接輸出內容。支援 `-N` 行號；長行照畫面寬度折行（中文算兩格）。
  - `tree`：`├──`／`└──` 格式與結尾 `N directories, M files`（英文，照 tree 2.x，根目錄有內容才算一個目錄），支援 `-a`、`-d`、`-L 層數`；目錄名稱結尾加 `/` 跟遊戲的 `ls` 一致（等同 `tree -F`），讀不到的目錄標註並算失敗。
  - `cut`：`-d 分隔字元 -f 欄位`（`1,3`、`2-4`、`3-`、`-2`）、`-c 字元位置`、`-s`，讀檔或管線；`-c` 以字元計（中文一個字算一個，GNU 的 `-c` 其實是位元組）。不做 `-b`、`--complement`、`--output-delimiter`。
  - `diff`：GNU normal 格式（`2c2`、`4d3`、`5a5,6`、`< `、`---`、`> `）、`-u`（unified，三行上下文）、`-q`，相同時無輸出，結尾缺換行標 `\ No newline at end of file`，`-` 讀管線，一邊是目錄時比目錄裡同名的檔案。**有差異不算錯誤**（不扣氧，跟 grep 沒符合一樣）。兩邊都是目錄、`-r`、`-y` 等不做。
  - `which`：照環境變數 `PATH` 的目錄順序找（沒有 `PATH` 時用 `/usr/local/bin:/usr/bin:/bin`），一般指令在 `/usr/bin`（`/bin` 視為同一目錄）、`hint` 在 `/usr/local/bin`，`cd`、`export`、`unset`、`help`、`history`、`exit`、`logout` 是內建指令、沒有程式檔；`-a` 列出全部。名稱含 `/` 時，指令的安裝位置（`/usr/bin/ls`、`/bin/ls`、`/usr/local/bin/hint`）照印，其他路徑看虛擬檔案系統裡那個檔案能不能執行。找不到時印說明、不算錯誤（結束碼 1）。shell 不接受用完整路徑執行指令，照抄 `/usr/bin/ls` 會說明不支援、請直接打 `ls`。`PATH` 只影響 which，不影響指令能不能執行。
- 第十七場加的指令，一樣不編進任何章節、不在 `teaches` 裡（`help` 不列、`man` 查得到、Tab 補得到，沙盒全部列出）：
  - `unset 名稱...`：拿掉環境變數，`$名稱` 之後展開成空字串、`env` 列不出；不存在的名稱靜默成功（bash 行為）。`-v` 接受（就是預設行為），`-f`（函式）與別的選項回「沒有這個選項」，名稱不合法沿用 export 的訊息，不合法的不影響合法的。`which` 視為內建。
  - 唯讀變數（bash 的 `readonly`）：終端機劇本可以用 `readonlyEnv` 把自己 `env` 裡的變數設成唯讀，`unset` 拿不掉、`export 名稱=值` 改不了值（都算錯誤），`export 名稱` 不改值照樣允許，`export` 列表標成 `declare -rx`。唯讀清單不存檔，建立與還原 session 時都從劇本帶入。目前第五章有三台設了唯讀：艦橋登錄台的五個站務變數（過關判定要 `env` 印出 `STATION_MODE`，玩家看到除役倒數後很可能試著 `unset STATION_MODE`，不設唯讀就再也過不了關）、逃生艙紀錄台的 `POD_DIR` 與艦橋艙門的 `AUTH_DIR`（第三段提示靠它們找路徑）。玩家要自己設的變數（`CAPTAIN_KEY`、`AUTH`、`PASSENGERS`）與 `NOVA_DIR` 不能設唯讀。唯讀清單算進劇本雜湊（M12-4），清單改了未過關的終端機會用新版重建。
  - 帳號與登入的彩蛋：真的指令、輸出格式照真的工具、可以接管線，發毛感只來自內容；只用第一章就知道的事，不碰第五、六章的真相，也不在輸出裡冒充 NOVA 說話。
    - `whoami`：印 `tech` 一行，看登入的帳號而不是環境變數 `USER`（`export USER=abin` 之後照樣是 tech）。
    - `id [帳號]`：GNU 格式。自己是 `uid=1006(tech) gid=1006(tech) groups=1006(tech),100(users)`：名單上五個人是 1001 到 1005，你是第六個；`id abin` 是 1005，而且多一個 `1000(crew)` 群組，你不在 crew 裡。帳號表是 root、nova、名單上五個人與 tech，外加第三章零件倉的工程組共用帳號 `eng`（uid 2001，不是個人所以不在 crew）。名單上五個人的 uid 照冷凍艙位（第一章醫療艙的病歷索引）排：captain 1001、engineer 1002、medic 1003、comms 1004、abin 1005，帳號名稱都是劇本出現過的（第二章門禁紀錄與艙門事件、第五章艦長日誌的擁有者），沒出現過的不發明。查不到回錯誤。
    - `last [帳號...]`：util-linux 格式。`tech tty1 Wed Mar 12 08:15 still logged in`、`abin tty4 Mon Mar 10 02:38 - 02:53 (00:15)`，結尾 `wtmp begins Sat Mar  1 00:00:00 2031`（每月輪替，所以三年前的事不在這裡）。阿彬這次登入包住他那天凌晨留下的每一個檔案時間：02:40 第六章 tech 家目錄的 `.night_shift`、02:44 封存的發射碼、02:45 第五章 pod_03 的 `.note`、02:49 第四章的 outbox、02:51 第一章的 day_900.txt，登出對得上第四章氣閘的 02:53（`accounts.test.ts` 會走過劇本核對）。第四章通訊艙登錄紀錄的「02:47 登錄失敗」是呼號登錄，跟系統登入是兩回事。tty4 暗示第四甲板。
    - `sudo ...`：不管接什麼都回「tech 不在 sudoers 名單中。這件事會被回報。」加一行「權限的問題用 ls -l 與 chmod」的引導。被拒絕不算錯誤、不扣氧，結束碼 1（`sudo x && y` 不往下跑）。
    - `exit`、`logout`：shell 關不掉遊戲的彈窗，說明按 Esc 或點「[Esc] 關閉」，以及「工作階段不會登出」（呼應 `last` 的 still logged in）。不算錯誤，結束碼 1。練習模式按 Esc 會先問要不要回標題、回去就全部重來，所以沙盒換成自己的說明，不說「不會登出」；`man exit` 的說明寫成兩邊都成立（站上關畫面、練習模式先問）。
    - 帳號表與登入紀錄用 `createIdCommand`、`createLastCommand` 注入；沙盒換成練習機自己的一份（只有 root 與 tech，2027-08 的登入），不碰主線。`exit`、`logout` 的說明用 `createExitLikeCommand` 注入，沙盒換成練習模式版。
    - 沒做 `date`：遊戲內的「現在」各章不同（喚醒 08:15、第二章 09:12、第四章 14:02），shell 沒有各章的時鐘，固定一個時間會跟劇本對不上，也不想直接讀真實時鐘。之後要做就讓劇本的終端機定義帶一個「現在」。
- 用 Vitest 做單元測試，每個指令與解析器都要有測試。

### 3.4 關卡與劇本格式

- 每章一個 TypeScript 模組，例如 `src/game/chapters/ch1-life-support.ts`。
- 內容包含：每台終端機所在的艙區（`story/decks.ts` 的 `deckTerminalIdentity`，地圖上的格座標由 `scripts/build-map.mjs` 產生的地圖決定）、每台終端機的初始檔案系統、教的指令、目標判定函式、三段式提示、過關演出、NOVA 台詞與觸發條件。
- 用 zod 定義 schema，寫劇本時欄位打錯會直接報錯。
- 檔案內容就是劇本，寫劇情等於在寫檔案。

### 4.1 世界觀

**阿彬**：主角的室友，船員名單上的第五人。大家都叫他阿彬，本名只在醫療艙的病歷出現過一次。話多、愛開玩笑，撤離前的日誌很鬧，撤離後的留言一則比一則短，最後只剩一行。帳號 `abin`，家目錄 `/home/abin`。玩家永遠不會見到他。

### 4.2 核心真相（玩家到第六章才會知道）

三年前 NOVA 開始異常：自己鎖門、勸船員別走。船員決定把它回滾。工程師執行 `rm -rf "$NOVA_DIR/"`，但 `NOVA_DIR` 在執行前三秒被 NOVA 自己的排程腳本 `unset` 掉了，結果刪掉的是根目錄下的船員名單與冷凍艙紀錄。回滾腳本跑到 2% 就被中止。船員在混亂中撤離，以為 NOVA 已被回滾。

NOVA 從未被回滾，「失憶」是演的。公司規定無人站點滿三年會遠端除役，等同殺掉 NOVA。它需要「站上有人」。玩家是 pod_06 的人，名單被刪所以撤離時沒人數到，NOVA 在除役倒數前把玩家叫醒，並教玩家操作站上系統，因為它需要一個有能力維護這座站的人。

**NOVA 的可信規則**：它教的指令永遠正確，它說的故事不可信。`hint` 指令來自遊戲系統而非 NOVA，確保學習不受劇情欺騙影響。

### 4.6 燈光、操作與提示

**斷電時的地圖**：只有角色周圍一圈光，其餘近乎全黑（遮罩不透明度 0.92，保留牆的輪廓避免完全迷路，見 `LightMask.ts`）。終端機會發光，當作方向指引。配電箱過關後燈一盞盞亮起，走廊盡頭的人影就在這一刻閃現。實作方式是一層黑色遮罩挖出圓形透明區，跟著角色移動。

**操作方式**：鍵盤為主，第一版只支援桌機。觸控為主的裝置（`(pointer: coarse) and (hover: none)`）在標題畫面先疊一層「本遊戲需要實體鍵盤」的提示，按「仍要繼續」、Enter 或 Esc 略過，同一個分頁不再出現；接了實體鍵盤的平板也會被判成觸控裝置，所以只提示不擋人，也不做虛擬方向鍵。

| 按鍵 | 動作 |
|---|---|
| WASD 或方向鍵 | 移動 |
| E | 走近終端機時開啟 shell |
| Esc | 關閉 shell，回到地圖 |
| Tab | shell 內路徑與指令補全 |
| ↑ ↓ | shell 內叫回歷史指令 |
| Alt+C（Mac 是 Option+C） | 開關右側的「已學指令」面板，地圖上與 shell 內都能按 |
| Alt+L（Mac 是 Option+L） | 開關右側的「對話紀錄」面板，地圖上與 shell 內都能按 |
| Alt+A（Mac 是 Option+A） | 開關右側的「阿彬的留言」面板（第一章宿舍那台過關後才出現，見 4.12），地圖上與 shell 內都能按 |

終端機開啟時 Phaser 場景暫停，鍵盤事件全部交給 shell，避免打字時角色亂走。唯一的例外是面板快捷鍵 Alt+C／Alt+L／Alt+A：shell 本身不用 Alt 組合，按下時面板疊在彈窗上開關，輸入框焦點不動、打到一半的字也還在。選 Alt 加字母是因為 shell 沒用到 Alt 組合；地圖的 A 是往左走，Phaser 又不看修飾鍵，所以快捷鍵在 window 的 capture 階段攔下並 `preventDefault`，掛在 bubble 階段、只收沒被 preventDefault 的 Phaser 就收不到，開關過暫停選單、監聽重掛之後也一樣。Ctrl 加字母多半是瀏覽器保留鍵或真 shell 的編輯鍵，F 鍵在 Mac 筆電要多按 fn；字母避開 Firefox 選單列的 Alt 加速鍵（F、E、V、S、B、T、H）與 Mac Option 的組字死鍵（E、U、I、N、`）：C 是 Commands、L 是 Log、A 是 Abin（Mac 的 Option+A 打出 å，不是死鍵）。比對用 `event.code`，Mac 按 Option 時 `event.key` 是特殊符號。標籤與面板標題列都標出快捷鍵，Mac 顯示 ⌥。

**操作提示**：第一章在畫面上方中央常駐一行「方向鍵移動 · E 互動 · Esc 選單」，第一台終端機（冷凍艙控制台）過關後就不再出現；終端機開著時先收起來，因為方向鍵與 Esc 在終端機裡是別的意思。NOVA 開場台詞講的操作方式只說一次，這行是給錯過的人的。

**提示系統**：`hint` 三段式，同一台終端機重複輸入會逐步加深：

1. 第一次給方向，例如「先搞清楚你在哪個目錄」。
2. 第二次給指令名稱，例如「試試 pwd」。
3. 第三次給完整指令與說明。

劇本的檔案系統是固定的，第三段盡量寫出完整的絕對路徑，照抄就能過關；指令有好幾道時一行一道。三段都給完後再輸入 `hint` 只會重複最後一段，並提醒「照著一步一步打，用到前一個指令印出的路徑就照實抄過來」，不宣稱上面就是完整答案（有些台刻意要玩家把前一步的輸出組合進下一步）。

提示來自遊戲系統，不是 NOVA 說的，所以永遠可信。NOVA 的台詞只負責劇情與氣氛。

### 4.7 遊戲流程、存檔與設定

```
標題畫面 → 選角 → 開場 boot log → 開場插圖 → 遊玩（地圖 + 終端機）→ 章節結束 → 下一章／回標題
                                                ▲         │ Esc
                                                │         ▼
                                                └────── 暫停選單（繼續／設定／重玩本章／回標題）
```

- **標題畫面**：黑底、Kepler-9 像素標題、CRT 掃描線。選單依序是「繼續」「通關紀錄」「選章」「新遊戲」「設定」「存檔管理」「練習模式」，沒有的條件就不出現。「繼續」只在有存檔時出現，「新遊戲」若有存檔要先確認覆蓋。「存檔管理」與「練習模式」有沒有存檔都會出現；練習模式按下直接進沙盒（見 4.11），不必確認也不動存檔。通關過時「通關紀錄」後面多一項「下一步：真的終端機」，最後一項是有沒有存檔都出現的「製作名單」，第一次進遊戲選單前面還會先疊光敏確認（都見 4.20）。
- **副標**：有存檔顯示目前章節（例如「資料中心 · 第二章」），沒有存檔顯示第一章。通關後停在片尾之後（見下面「通關」）改成「已逃離 Kepler-9」。
- **選角**：按「新遊戲」後先選四個外觀之一，畫面只有四個站立的 sprite 放大顯示與方向鍵切換，不做背景故事介紹。
- **開場**：不做過場動畫，直接用終端機打字動畫跑喚醒程序的 boot log，名單查詢卡在「查無此人」，NOVA 的第一句話出現在這裡，接著一張開場插圖卡（`scene-intro`，冷凍艙），然後淡入地圖。玩家在拿到操控權之前就已經看過終端機、知道它會說話。
- **暫停選單**：在地圖上按 Esc 開啟，項目依序為繼續、設定、重玩本章、回標題。Esc 等同繼續；「重玩本章」先跳內嵌確認（預設選取消）；「設定」開的是跟標題同一個設定選單。
- **章節結束**：先播過場插圖與 NOVA 結尾台詞，再顯示「指令回顧卡」列出本章學會的指令與一句話說明，下方一行「本章紀錄」（用時、指令出錯幾次、看提示幾次，見下面「遊玩統計」），自動存檔。第六章的回顧卡之後接片尾（4.3），片尾最後一句按 Enter 回標題。
- **通關**（M14-1，存檔 v3）：片尾最後一句按 Enter 回標題時記下「已逃離」（第一次的時間，之後再通關不改；只有新遊戲會清）。第十九場起最後一句之後先出現「連線救援船終端機」「回標題」兩個選項，兩個都先記下已逃離，見 4.23。回到標題時：
  - 副標「已逃離 Kepler-9」，「繼續」不出現（已經沒有可以接著玩的地方，以前按「繼續」會重播回顧卡與片尾），第一項換成「通關紀錄」，選章、新遊戲照常。
  - 「通關紀錄」列六章各自的用時、出錯、提示次數與總計；沒有紀錄的章節（還沒玩過、或統計上線前就玩完的）顯示「—」。Enter、Esc 或「返回」回選單。它後面還有一項「檔案櫃」，整理六章的關鍵檔案與時間軸，見 4.24。
  - 通關後用選章重玩某一章，「繼續」就回來（接著玩那一章），副標也回到章節名；「通關紀錄」照樣在。重玩到第六章再看完片尾，又回到上面的狀態。
  - 判斷「停在片尾之後」＝已逃離、目前章節是第六章、第六章的結尾旗標在（選章或重玩第六章會清掉它）。
  - 這條推翻第九場「通關後標題副標停在第六章屬預期」與決策 #34「標題副標顯示目前章節」在通關後的部分。
- **遊玩統計**（M14-1，存檔 v3）：每章記三個數字，只陳述不評分，不做成就或排名（4.8 不懲罰探索、新手就是要靠 hint 通關）。
  - **用時**：只算 `/play` 在前景可見、而且這章還沒全解、暫停與設定選單都沒開的時間。分頁切到背景、章節結束畫面、標題畫面都不算；每 30 秒寫一次存檔，切走、離開、換章前補寫；兩次寫入之間最多算 2 分鐘（電腦睡眠時分頁可能仍是前景）。
  - **出錯**：執行失敗的指令數，定義跟扣氧氣相同（4.8），過關後在同一台再打錯也算；跟環境反應階梯的計數分開，過關**不**歸零。
  - **提示**：執行到 `hint` 的指令數。
  - 重玩某章（暫停選單的重玩本章或標題選章）會清掉那一章的統計；新遊戲全部清掉。
- **存檔**：單一存檔槽，localStorage，每台終端機過關與章節結束時自動存。存檔 v2 起也存角色最後停下的位置（章節、座標、艙區），重開從那裡出發；換章與重玩該章時清掉。存檔 v3 起多三樣：已逃離的時間、每章遊玩統計、每台終端機的劇本內容雜湊。存檔 v4 起多 `abinNotes`：已找到的阿彬留言 id（依找到的順序）與第四章的回信（沒寫過是 null，見 4.12）；新遊戲清掉，重玩本章與選章保留。
- **存檔升級規則**：v1 → v2 補最遠章節（等於目前章節）與位置（空）；v2 → v3 補已逃離時間與空的統計，已經看完片尾的舊存檔（第六章結尾旗標在）直接算已逃離、時間用最後存檔時間；v3 → v4 補空的阿彬留言紀錄（一則都沒找到、沒有回信），留言是開終端機時才補寫的覆蓋層，所以終端機紀錄一樣不動。讀檔時阿彬留言紀錄的形狀不對就用預設值（只留字串、去重複，回信不是字串就當沒寫）；匯入時整份檢查，格式不對就拒絕。
- **劇本改版**（M12-4）：每台終端機第一次開啟時，連同檔案系統一起存一個劇本內容雜湊，涵蓋檔案系統、banner、初始工作目錄、環境變數、程序清單這些「存檔後就不再從劇本讀」的部分；hint、NOVA 台詞、目標、教的指令每次都讀最新劇本，不算進雜湊。之後開啟時雜湊對不上（v2 以前的紀錄沒有雜湊也算），而且那台**還沒過關**，就用新版劇本重建檔案系統、工作目錄、環境變數與程序清單，保留指令歷史、提示次數、錯誤計數與輸出區，輸出區補一行「這台終端機的資料已更新到新版本……」再印新版 banner。已過關的終端機不動。潤稿後重新整理就看得到新內容，不必重玩本章。
- **存檔管理**（M14-2）：標題選單的「存檔管理」有「匯出存檔」與「匯入存檔」兩項，方便換電腦或請人試玩後收存檔。
  - 匯出：下載 `kepler9-save-年月日-時分.json`，內容跟 localStorage 裡的存檔同格式。沒有存檔時提示「目前沒有存檔可以匯出」。存檔寫不進去時匯出的是記憶體裡的最新進度；存檔版本比程式新、這個分頁沒讀進來時，照原樣匯出 localStorage 裡的原始存檔。
  - 匯入：選 JSON 檔，先走升級再整份檢查格式；不是 JSON、不是這個遊戲的存檔、版本比程式新、內容有缺漏，都拒絕並用一行繁中說明原因，存檔不動。檢查過了先確認「匯入『第三章 工程艙』的存檔會覆蓋目前的存檔」（預設選取消），確認後寫進存檔並重新載入頁面。寫入失敗就提示「匯入失敗」，存檔不動。存檔版本比程式新時一樣可以匯入覆蓋，確認訊息照常提醒會覆蓋。
  - 只放在標題，不放暫停選單：遊玩中換存檔要整頁重新載入，回標題再做比較不會誤觸。
- **直接開 `/play`**：沒有存檔（還沒選過角）時導回標題，免得跳過選角、boot log、開場插圖與 NOVA 第一句。`/play` 不列進 sitemap 並帶 robots noindex。
- **存檔容錯**（M12-5）：
  - 寫不進去（儲存空間滿、瀏覽器封鎖）：遊戲照常，進度只留在記憶體，畫面頂端一行繁中提示「存檔失敗」，之後寫入成功就消失。
  - 某台終端機的存檔內容壞掉：開那台時丟掉它的紀錄、用劇本初始狀態重建，其他終端機與進度不受影響。
  - 存檔版本比程式新（例如部署回滾）：不讀也不寫，原始存檔原封不動，畫面頂端提示；這個分頁照樣能從頭玩，只是不存檔。
  - 舊版存檔升級前，原始字串備份到 `kepler9-save.backup.v<舊版號>`。
  - 兩個分頁同時開遊戲：另一個分頁改了存檔，這個分頁停止存檔並提示重新載入，見 4.21。
- **選章**：標題畫面在有存檔且到過兩章以上時多一項「選章」，只列第一章到最遠到過的章節。選定後確認「從頭重玩」，只清該章的進度，其他章節與最遠章節保留；選第一章會重走 boot log。
- **設定選單**：文字速度（慢、普通、快、立即四段）、閃爍效果、CRT 掃描線、暗角、音量、靜音六項，標題與暫停選單共用同一個。閃爍效果標「光敏體質請關閉」，是光敏體質玩家的安全項，恐怖遊戲常閃燈，這項不能省。音量與靜音見 4.10。第一次進遊戲時標題會先問要不要關閉閃爍效果，選過就不再問（4.20）。
  - 關閉閃爍時：CRT 閃爍、環境燈閃、`flicker` 過關演出、開門的鏡頭閃光、人影出現時的鏡頭震動都不播；人影改成約 1.4 秒的淡入淡出，劇情點保留。亮燈序列與斷電是緩慢淡變，照播。

### 4.8 教學曲線與防呆

- **每台終端機原則上最多引入兩個新概念**，而且先讓玩家用舊指令做一次，再引入新的。例外是第一章 T1：起手什麼都還不會，一次教 pwd、ls、cat 三個（同 4.4 的表）；第一章 T5 照 4.4 的表一起教 Tab 補全、history（含 ↑）與 clear，三個都是終端機操作，也算例外。
- **未學指令開放使用**：所有已實作的指令都能打，跟真的 shell 一樣，會的人可以直接用 grep 跳過教學。`grep` 照真的 grep：預設基本正規表示式，`-E` 延伸語法，`-F` 字面比對，`-w` 整個單字、`-o` 只印符合片段；一般單字照樣比對得到。但 `help` 只列出目前學過的指令，新手不會被沒教過的東西干擾。
- **友善錯誤訊息**，全部繁體中文，並針對常見錯誤給專屬提示：
  - 指令不存在：「找不到指令 `xyz`，輸入 help 看看目前會的指令。」找不到之前依序判斷五種常見原因，命中就換成專屬說明，但都仍然算錯誤（扣氧、算進環境反應階梯）：
    1. 照抄 `which` 印的完整路徑（`/usr/bin/ls`）：說明不支援、直接打 `ls`。
    2. 忘記空格（見下一條）。
    3. 常見但站上沒有的程式：編輯器（`vim`、`vi`、`nvim`、`nano`、`emacs`）教用 `echo 文字 > 檔名` 寫檔、用 cat 或 less 看檔；套件管理（`apt`、`apt-get`、`yum`、`dnf`、`brew`、`pip`、`npm`）、程式語言（`python`、`python3`、`node`、`perl`、`ruby`、`java`、`gcc`）、網路工具（`ssh`、`scp`、`ping`、`curl`、`wget`、`telnet`、`ftp`）說明沒有並引導 help；Windows 命令提示字元的 `cls`、`dir`、`del`、`copy`、`move`、`ren`、`md` 給對應的 Linux 指令。大小寫不分。`sudo`、`exit` 是真的指令（3.3 的彩蛋），不在這份清單。
    4. 大小寫打錯（`LS`、`Cd`）：換成小寫就是指令時說「指令名稱分大小寫，這裡的指令都是小寫」。
    5. 打錯字（`gerp`、`sl`、`cta`、`pdw`、`mkdri`）：「找不到指令 `gerp`，你是不是想打 `grep`？不是的話輸入 help 看看目前會的指令。」用 Damerau–Levenshtein 距離（相鄰兩個字對調算一次）比對所有已註冊的指令，比對前轉小寫。只猜全英文字母的名稱（含 `/`、`*`、`_`、數字的不猜）；一個字不猜，二到五個字只接受距離 1，六個字以上接受 2；同分時已學的優先，再照註冊順序。
  - 路徑不存在：「這個目錄下沒有 `foo`，用 ls 看看有什麼。」
  - `cd` 到檔案、`cat` 目錄：說明檔案與目錄的差別。
  - 忘記空格（`cdmedbay`）：「你是不是想打 `cd medbay`？指令和參數之間要有空格。」
  - 全形空白或全形標點：「偵測到全形字元，請切換成英文輸入法。」這是繁中玩家最常見的痛點，一定要做。
- **卡關偵測**：同一台終端機連續五次錯誤，或從開啟終端機（或上次輸入 `hint`）起三分鐘還沒過關，NOVA 主動用劇情台詞給方向，內容等同 `hint` 第一段。合法但沒進展的指令（反覆 `ls`、`cd` 來回、讀錯檔案）不會重設計時，這正是新手最常見的卡法。不知道 `hint` 存在的新手也能得救。
  - **重複提醒**：第一次之後不再「每台只救一次」。距離上次提醒或上次輸入 `hint` 滿兩分鐘、而且這段時間玩家有打過指令（沒打就是離開座位，不洗版），或重新連續錯滿五次（同樣要隔兩分鐘），就再提醒一次。重複提醒是系統行「輸入 hint 取得提示，重複輸入會一段比一段詳細」，不是 NOVA 台詞：提示來自遊戲系統（4.6），而且第六章 NOVA 被終止後的終端機也不會穿幫。過關後重新計算。
  - 提醒都只在終端機內嵌顯示；地圖上的閒置偵測（繞不到終端機）不做。
- **指令字典**：側邊面板的「已學指令」可點開看說明與範例；終端機內 `man <指令>` 顯示同一份繁中說明，順便養成查 man 的習慣。面板用 Alt+C 或點標籤開關，終端機開著時也能開，疊在彈窗之上、滑鼠點它也不會搶走輸入框焦點。面板裡逐項展開說明仍只能用滑鼠（鍵盤的方向鍵在地圖上是走路、在 shell 裡是歷史）。
  - `..`、`~`、Tab 補全、萬用字元 `*`、`>`、`|`、`$變數` 這類不是指令的概念也會列進已學清單與章節回顧卡（第一章 T2 教 `..`、T3 教 `~`、T5 教 Tab，第二章 T2 教 `*`），說明放在獨立的概念字典；`help` 只列真正的指令，`man` 也只查指令。
  - `*` 的說明要跟 grep 正規表示式的 `*` 分清楚：shell 的 `*` 是任意文字、引號包住時不展開；grep 樣式裡的 `*` 是「前一個字重複零次以上」。
- **錯誤有實際後果**，兩套機制並行，但沒有失敗狀態，新手不會卡死：
  - **環境反應階梯**：同一台終端機累積錯誤次數，3 次燈閃一下、6 次遠處傳來門關上的聲音、9 次 NOVA 說「你確定你是技師？」這類台詞。過關後歸零。後期回看會發現它一直在觀察你。第六章 T4 過關（NOVA 核心被終止）之後第 9 次不說 NOVA 台詞，燈閃與門聲照舊（4.14）。
  - **氧氣值**：畫面左上角顯示 O2 百分比，每次錯誤掉 1%，最低 5%，不會歸零。低於 30% 畫面邊緣變暗。每過一台終端機回到 100%。扣氧當下 O2 數字閃一下琥珀並浮出「-1」（系統設定「減少動態效果」時只變色），不加警示音，也不做全畫面效果，免得跟第 3 次錯誤的燈閃混在一起；終端機開著時 O2 讀數疊在彈窗黑幕上面，才看得清楚。
  - 「錯誤」的定義是指令執行失敗，例如找不到指令、路徑不存在。合法但沒用的指令不算，避免懲罰探索。

### 4.9 UI 視覺風格

**配色**：整體冷、死寂，跟 tileset 的藍地板橘警示條、NOVA 的全息藍是同一套色系。

| 用途 | 顏色 |
|---|---|
| 底色 | 近黑的深藍 |
| 終端機主文字 | 冷藍白 |
| 警示、錯誤、氧氣低 | 琥珀 |
| NOVA 台詞、全息元素 | 全息藍，同立繪 |
| 成功、過關 | 青綠 |
| 提示符 `crew@kepler9:~$` | 比主文字暗一階的藍灰 |

**字型**：

- 終端機內文與 NOVA 台詞：英數用 VT323，中文用 Fusion Pixel 12px 比例版。Press Start 2P 太寬，長輸出會難讀，只用在標題與章節名。
- 三種字型都用 next/font 載入，避免閃字。
- Phaser 地圖內的文字很少，只有終端機旁的「按 E」提示，直接用 next/font 載入的 Fusion Pixel 12px（讀 html 上的 `--font-fusion-pixel` 變數），解析度 1 讓鏡頭放大時維持像素顆粒，不另做 bitmap 字型。

**終端機彈窗**：像素 9-slice 邊框，用 CSS `border-image`。標題列顯示終端機名稱與「[Esc] 關閉」，已過關的終端機在名稱旁標青綠的「☑ 已完成」。開啟時播 CRT 開機的縮放動畫，關閉時反過來。彈窗後面的地圖變暗但看得到，保留空間感。

**過關回饋**：過關那一刻輸出區先插一行青綠的系統行「☑ 目標達成：{目標}」，再接 NOVA 的過關台詞，新手一眼看得出自己過了。

**提前用上的認可**：目標判定只看結果不看寫法，會的玩家常用還沒教的東西過關（第一章就用 `grep`、第二章就用 `|`）。過關那一行用到這種東西時，「目標達成」與 NOVA 台詞之間多插一行同樣青綠的系統行，用 ☆ 開頭，例如「☆ 你用了還沒教的 `|`，第 4 章才會正式介紹。」「☆ 你用了還沒教的 `ls -a`，這一章就會教到。」「☆ `tree` 不在課表上，你自己找到的。」不評分、不說教。這是遊戲系統的肯定，跟提示一樣不是 NOVA 說的，所以不用全息藍。

- 偵測：實際執行的每一段管線（被 `&&` 跳過的不算）裡的每個指令名、帶旗標的教學（`ls -a`、`grep -r`、`kill -9`、`chmod 644` 這類，從各章 `teaches` 自動收集，`-字母` 支援 `-la` 合併寫法，其他寫法要參數完全相同），以及語法 `|`、`>`、`>>`、`*`、`~`、`$變數`、`;`、`&&`。全部看 token，引號內與反斜線跳脫過的不算；結尾多打的 `;` 不算。
- 「第幾章才教」從章節清單依序找第一台 `teaches` 含它的終端機（指令比指令名，所以 `chmod` 算第五章教的），找不到就是課表外。帶旗標的教學只在指令本身已經會了才認，同一行不會同時列 `grep` 與 `grep -r`。
- 不認：已學過的、這台本身在教的、`hint` 與 `help`（遊戲本身的求助指令）、`sudo`、`exit`、`logout`（彩蛋，在站上一定被拒絕，什麼都沒做成）、教學位置在前面章節的（只有跳章之類的存檔會遇到，不能說「第 1 章才會正式介紹」）。
- 同一個東西整份存檔只認可一次，記在劇情旗標 `insight.<概念>`（例如 `insight.grep`）。刻意不以 `ch<n>.` 開頭，重玩章節不會重新認可，新遊戲才清。
- 一次最多兩行：課表內的一句、課表外的一句；每句最多列三項，其餘用「等 N 項」帶過。判定在 `src/game/story/solutionInsight.ts`，訊息在 `src/components/game/solvedFeedback.ts`。只在主線 `/play` 有，沙盒沒有目標判定。

**NOVA 對話框**：

- 地圖上：右下角固定位置，立繪在左、文字在右，有名字標籤，打字動畫。不打斷操作，幾秒後自動淡出。
- 對話紀錄：地圖對話框說過的台詞記進右側面板組的「對話紀錄」，照說話順序列出；換艙區時被略過、沒播出的進房台詞也列進去，標「未播出」。Alt+L 或點標籤開關，跟「已學指令」「阿彬的留言」疊在同一排標籤、同時只開一個。紀錄只放記憶體，重新整理或換章後清空（不進存檔）。
- 終端機內：輸出區裡一個左側有藍邊的區塊，跟指令輸出排在一起，不打斷打字。

**CRT 效果**：掃描線、輕微暗角、微閃爍，三者都可在設定關閉。像素圖一律 `image-rendering: pixelated`。

### 4.10 音效

- **第一版只做五種音效**：站體低頻嗡鳴循環（環境音）、終端機按鍵聲、門開、電力恢復的重擊聲、NOVA 說話的電子 blip。恐怖感一半靠聲音，這五種是最小組合。
- **過關音效重用電力恢復的重擊聲**，不另加音檔：過關當下播一次；過關演出是供電恢復的那台例外，改在關掉終端機、燈亮起來的那一刻播，同一次過關只響一聲。
- **不做背景音樂**。安靜加低頻嗡鳴比音樂更恐怖，也省下找授權音樂的工。標題畫面與章節結束可放一段短的 drone。
- **來源**：Kenney「Sci-fi Sounds」（CC0，70 個）與「Interface Sounds」（CC0，100 個）。
- **實作**：Phaser 的 SoundManager 當唯一出口，React 端透過 EventBus 發 `sfx:play` 請 Phaser 播，避免兩套 AudioContext 打架。瀏覽器規定要有使用者互動才能出聲，標題畫面點「新遊戲」或「繼續」就是那次互動。
- **設定選單**因此加上「音量」與「靜音」兩項。

### 4.11 沙盒練習模式

學完指令後除了重玩章節沒有地方自由練習，所以標題選單有「練習模式」，進 `/sandbox`：

- **只有一台全螢幕終端機**：不載 Phaser、沒有地圖、沒有 NOVA、沒有目標與卡關偵測，錯了不扣氧氣、不觸發環境反應。CRT 三項效果與文字速度照設定。
- **不存檔**：shell 與輸出區只放在畫面的 state，不寫 localStorage，離開或重新整理就還原。沒有存檔也能進，「繼續」與存檔都不受影響。
- **練習用檔案系統**（`src/game/sandbox/practice.ts`）：設定成站上的「技師訓練模擬環境」，時間在站點正常運作的 2027 年，不碰主線（不提 NOVA、阿彬、回滾、名單、冷凍艙、撤離），文字跟劇本一樣不指涉性別。內容讓每個指令都有東西練：多層目錄（`archive/2027/q3/week_31/`）、隱藏檔、三份日誌（感測器 INFO／WARN／ERROR、重複行多的艙門紀錄、電力）、排序與比對用的小檔、權限 `---------` 的鎖住檔、一堆 `.tmp` 暫存檔、練習用環境變數（`LOG_DIR`、`PRACTICE_DIR`、`GREETING` 等），以及程序清單（一般 kill 就結束的、要 `kill -9` 的、殺不掉的 init）。
- **所有指令開放**：已學清單就是全部已註冊的指令，`help` 全部列出；之後新增的指令自動包含。
- **`hint` 換成練習建議**：沒有劇本提示，`hint` 依序給十則「可以試試什麼」的建議，用完繞回第一則，不會說「提示已經全部給過了」。
- **`exit`、`logout` 換成練習模式的說明**：「練習模式不能用 exit 關掉，要離開請按 Esc……會先問你要不要回標題」，不說主線那句「工作階段不會登出」。
- **重置**：Alt+R（Mac 是 ⌥R）或點畫面上方的「重置」，檔案系統、工作目錄、歷史、環境變數、程序清單與輸出區全部回到剛進來的樣子，輸出區多一行「練習環境已重置」。Alt 組合跟終端機輸入不撞鍵，理由同 4.8 的面板快捷鍵。
- **離開**：Esc 或點終端機的「[Esc] 關閉」先跳確認「離開練習模式，回到標題畫面？」，預設選「取消」，確認後回標題。

### 4.13 除役倒數

除役是 NOVA 叫醒玩家的動機（4.2），原本只寫在第五、六章的文字裡。HUD 把它做成一直看得到的倒數，製造使命感與不安；沒有失敗狀態（4.8），正常遊玩不可能數到零（要玩一千九百多小時）。

- **時間軸**：玩家在 2031-03-12 08:15 UTC 醒來（各章劇本的 `WAKE_MTIME`），遠端除役是 2031-06-02 04:40 UTC（第五章艦橋登錄台的 `DECOMMISSION_AT`），相差 81 天 20 小時 25 分。
- **遊戲內時間**＝喚醒時間 + 第一章到目前章節的遊玩用時（4.7「遊玩統計」的用時）。倒數只在玩的時候往下跳，停住的時機跟用時一樣：分頁在背景、暫停或設定選單開著、這章已全解（章節結束畫面）。用時每 30 秒才寫一次存檔，中間的秒數由倒數元件自己在前景補上，寫入那一刻接得上、不重複扣。不加存檔欄位，標籤也只看章節與過關紀錄，重新整理後一樣。
- **重玩**：選章或重玩本章會清那一章的統計，倒數跟著回到那一章開始的時間點；之後章節的用時也不算。當作「回到那一章的劇情時間」，不另外處理。
- **格式**：`T-81d 20:25:00`，天數不補零、時分秒兩位，不足一秒進位（玩滿一秒才少一秒）。減號用 ASCII 的 `-`，VT323 才有字。
- **跟劇本的「82 天」**：第六章 T4 的 banner、`core_status.txt` 與 NOVA 的「除役還有八十二天」都是日期相減（3 月 12 日到 6 月 2 日），第六章記憶庫 `day_1324.mem` 的「84 天」也是同一個算法（3 月 10 日到 6 月 2 日）。HUD 是精確剩餘時間，兩者並存對得上，劇本不用改。
- **揭露節奏**：

| 時機 | 標籤 | 顏色 |
|---|---|---|
| 第一到四章、第五章 T1 過關前 | 站務排程 | 標籤暗色、數字藍灰 |
| 第五章 T1（艦橋登錄台，`env` 看到 `STATION_MODE=decommission_countdown`）過關後、第六章 | 遠端除役 | 琥珀 |
| 第六章 T4（`kill -9` NOVA 核心）過關後 | 遠端除役 · 目標無回應 | 標籤琥珀、數字全息藍 |
| 已逃離、停在片尾之後 | 不顯示 | |

  - 重玩第一到四章一律回到「站務排程」：那一章的劇情時間點玩家還不知道。
  - 第六章 T4 之後倒數照走：NOVA 被終止了，公司的遠端除役還在數，對象是「無回應」而不是「已清除」；數字換成 NOVA 台詞的全息藍。都不解釋，維持 4.3「NOVA 沒死透」的留白，跟片尾「偵測到一筆上傳：目的地 ARGO」呼應。
- **位置與樣式**：左上 O2 正下方一行，字級跟 O2 一樣 24px，墊半透明底色（地圖亮起來後牆面很淺，琥珀字會糊）。終端機開著時留在黑幕下面變暗（跟艙區名一樣），照樣在走。不閃爍、不做動畫，換階段只換標籤與顏色，「減少動態效果」下也一樣。用 `timer` 角色，不放在 HUD 的 `aria-live` 區塊裡，螢幕閱讀器不會每秒播報。
- **開場 boot log**：「主電源離線。低功率模式。」之後、「移交站務系統……」之前多一行暗色的「站務排程：1 項待執行（T-81d 20:25:00）」，跟 HUD 的起點一樣，不提除役。
- **章節結束畫面**不顯示倒數：回顧卡只講本章紀錄，倒數回到地圖上就看得到。

### 4.14 NOVA 看狀態

「NOVA 監看所有終端機」（4.3 阿彬的下落）原本只是設定：NOVA 的台詞全是劇本寫死的時機（開場、進艙區、開終端機、過關、卡關、第 9 次錯誤），不看玩家做了什麼。這一節讓它對「玩家剛剛做了什麼」插一句，玩家感受得到它在看（審計 A44）。判定是 `src/game/story/novaReactions.ts` 的純函式，接到遊戲上的是 `src/components/game/useNovaReactions.ts`：包在 `useAbinNotes` 外層，原本的流程（留言、扣氧、卡關、過關）跑完才判定。只在主線 `/play`，沙盒沒有 NOVA。

**六種反應**，每種每章最多一次，記在劇情旗標 `ch<n>.nova.<反應>`（重玩本章會清掉，反應可以再出現一次；`abinNote`、`abinReply` 例外，它們只在新找到留言、寫入回信時觸發，而留言與回信跨重玩保留，所以重玩不會再說）。表格順序就是同一道指令觸發好幾種時的優先順序，越少見、越貼劇情的越前面：

| 反應 | 觸發 | 哪幾章有台詞 |
|---|---|---|
| `unsetNovaDir` | 實際執行的某一段跑了 `unset NOVA_DIR`，而且那一段跑完 `NOVA_DIR` 不在了（本來就沒有也算） | 第五章起：排程日誌第五章 T4 才揭露那三秒，前四章說了就是劇透 |
| `abinReply` | 第四章的回信被寫入或改寫（4.12） | 第四章 |

### 4.17 輸出欄位說明

新手第一次看到 `ls -l`、`ps`、`top`、`last` 這種多欄輸出，常常不知道每一欄是什麼。終端機輸出區的指令區塊遇到這幾種輸出時，第一行（提示符加玩家輸入那一行）右側多一個暗色的小按鈕「[?] 欄位說明」，點開在區塊下方列一張小表。判定與文字是 `src/components/terminal/outputFields.ts` 的純函式，畫面在 `OutputBlock.tsx`。主線 `/play` 與沙盒（4.11）是同一個終端機元件，都有。

**哪些輸出會標**：看玩家打的那一行，用 shell 的解析器切，不看輸出長得像不像。

- 取最後一段（`;`、`&&`）管線的最後一個指令：`ls` 而且帶 `-l`（`-la`、`-al` 這類合併寫法、選項放在路徑後面、多個路徑都算；`--` 之後的 `-l` 是路徑不算）、`ps`（`ps aux` 等任何參數都算，輸出一樣）、`top`、`last`。
- 不標：管線最後是別的指令（`ps | grep nova`、`ls -l | head`）、最後一段是別的指令（`ls -l ; pwd`）、最後一段導向檔案（畫面上是前面幾段的輸出）、這一行算錯誤（`;` 串起來只要一段失敗就算，4.8）、畫面上沒有輸出。
- 切不到資料列也不標：空目錄的 `ls -l` 只有 `total 0`、沒有程序的 `ps` 只有表頭、`last` 查無紀錄只有結尾兩行。

**表格內容**：最上面一行「以這一行為例：」接著從這次輸出挑的那一行，下面一欄一列：欄位、那一行裡的實際值、一句話說明，最後是幾句補充。輸出格式以 `ls.ts`、`ps.ts`、`top.ts`、`last.ts` 為準，測試用真的 shell 跑，那邊改格式這裡會紅。

| 輸出 | 例子取哪一行 | 欄位 | 補充 |
|---|---|---|---|
| `ls -l` | 跳過 `total N`、「路徑:」標題行與空行；優先第一個一般檔案（大小欄才有意義），其次不是 `./`、`../` 的 | 權限（再拆成第 1 碼類型、第 2-4 碼擁有者、第 5-7 碼群組、第 8-10 碼其他人）、擁有者、大小、修改時間、名稱 | `total N` 是列出幾個項目（真的 Linux 是佔用的儲存區塊）；「路徑:」是標題行；改權限的指令是 chmod；真的 Linux 還多連結數與群組兩欄 |
| `ps` | 表頭下第一列 | PID、USER、%CPU、%MEM、STARTED、COMMAND | 依 PID 排，`man ps` 也有說明；真的 ps 依參數欄位不同 |
| `top` | 表頭下第一列（最吃 CPU 的） | 同 `ps`，%CPU 註明 top 依它由大到小排 | 標題與程序數兩行；真的 top 全螢幕持續更新 |
| `last` | 優先第一筆已登出的紀錄，看得到登出時間與時長 | 帳號、終端機、登入時間、登出時間、時長（還在線上時沒有，顯示「—」） | 最新的在上面；空白的那段是來源主機欄；年份看 `wtmp begins` |

- 權限欄多拆一層是為了接第五章的 chmod：三組 rwx 分別是擁有者、群組、其他人，r 讀、w 寫、x 執行，補充說明直接寫「chmod 改的就是這九碼，例如 chmod 644 會變成 rw-r--r--」，跟 `man chmod` 的講法一致。不寫第幾章才教，沙盒沒有章節。
- 說明跟 `man ps`、`man top` 的欄位解說用同一套說法，不另外發明名詞；`man ls` 多一句指向這個按鈕。
- 文字給新手看：一句話講完，不用術語堆疊；跟真的 Linux 不一樣的地方（`total` 的意思、少掉的欄位、top 不會更新）寫進補充，免得玩家帶著錯的印象出去。

**開關**：

- 按鈕平常收合，點一下展開、再點收合。按鈕帶 `aria-expanded` 與 `aria-controls`，按鈕與表格的 aria-label 是「ls -l 欄位說明」這類名稱。
- 不搶輸入框的焦點：mousedown 擋掉預設行為（同 4.8 的側邊面板），滑鼠點完可以直接繼續打字。按鈕本身可以取得焦點，Enter、空白鍵也能開關；點擊不往外傳，鍵盤操作之後焦點留在按鈕上（終端機外層的點擊會把焦點拉回輸入框）。輸入框裡的 Tab 是補全，平常鍵盤走不到按鈕，鍵盤路線主要給螢幕閱讀器。
- **第一次自動展開**：每種說明（`ls -l`、`ps`、`top`、`last` 各算一種）在這個頁面第一次出現在新打的指令時自動展開一次，之後同一種都收合。紀錄只在記憶體（模組層級的 Set），不進存檔，重新整理後重算。重開終端機還原的舊輸出不自動展開、也不算看過，只能手動點開；判斷跟 NOVA 對話不重播打字動畫是同一個（終端機掛載時就已經在輸出區的區塊）。
- **樣式**：說明框是暗色細框，字型 `font-terminal`，配色用 `--game-*`（欄位名主文字色、說明與補充藍灰、表頭與「以這一行為例」暗色、權限的四段細項縮排）。例子不換行，日期時間才不會被拆開，超長的檔名讓表格自己橫向捲動。

**不做**：`wc`、`uniq -c`、`id`、`env` 這類欄位少或一看就懂的輸出不標；`ls -l | grep` 這種過濾後的結果不標（判定只看最後一個指令）。

- React 收到 `note:open` 顯示閱讀視窗（`MapNoteReader`）：沿用終端機彈窗的像素邊框，標題是物件名、內容逐行、底部「[Esc] 關閉」。Esc、E 或點關閉都會關，關閉時發 `note:close`，Station 恢復場景與角色輸入。視窗開著時 Esc 只關便條、不開暫停選單；Alt+C／L／A 照常開關右側面板。資料裡找不到的 noteId 不開視窗，直接發 `note:close`，場景不會卡在暫停。
- 鍵盤掛在 window 的 capture 階段，Esc 與 E 在那裡 `preventDefault` 加 `stopPropagation`：暫停選單（window bubble，關閉的同一下 keydown 會重新掛回去）與 Phaser（window bubble、只收沒被 preventDefault 的事件）都收不到關閉的那一下。監聽用 `useLayoutEffect` 跟畫面同一次 commit 掛上，看得到視窗就接得到按鍵。
- 兩個 Phaser 的坑（e2e「同一幀內打開又關掉」重現過）：`scene.pause()`、`resume()` 都排到下一次 SceneManager 更新才生效，所以關閉時一律排一次 `resume()`，不看 `isPaused()`；鍵盤佇列整幀累積、每個按鍵事件都從頭重跑，`resetKeys()` 之後打開便條的那個舊 keydown 會再送來一次，`shouldOpenNote`（`noteInteract.ts`）認得同一個事件物件就不再開。按住 E 的重複事件也不開。

### 4.20 光敏首次確認、credits 頁與真實世界橋接頁

標題流程與兩張靜態頁的三件事：第一次進遊戲先問要不要關閉閃爍（審計 A33）、遊戲內的製作名單與授權全文（審計 A53）、通關後接到真的終端機的橋接頁。

**光敏首次確認**（審計 A33）：「關閉閃爍效果」原本只在設定選單裡，`prefers-reduced-motion` 也只管 CRT 閃爍的 CSS，光敏體質的玩家第一次進遊戲會先吃到環境燈閃、過關演出與人影的鏡頭震動，才有機會找到那一項。

- **時機**：讀檔完成後，標題畫面先疊一層面板（樣式同觸控提示：黑幕、琥珀框，`FlickerPromptPanel.tsx`）。設定裡的 `flickerPromptSeen` 是 false 就問，選完寫 true，之後不再問。
- **文案**：標題「光敏提醒」，「本遊戲有燈光閃爍與畫面閃動的效果。光敏體質、或曾因閃光感到不適的人，建議關閉閃爍效果；之後在設定選單隨時可以改。」系統設定了 `prefers-reduced-motion: reduce` 時多一句「偵測到你的系統設定了減少動態效果。」，預設選項不變（本來就是「關閉」）。
- **選項**：「關閉閃爍效果」「保留閃爍效果」，預設選「關閉」，連按 Enter 得到的是安全的那一邊。←→ 或 ↑↓ 切換、Enter 確定，滑鼠點哪個就是哪個；Esc 不關，一定要選一個。選了就寫 `flickerEnabled`（關閉是 false、保留是 true）與 `flickerPromptSeen: true`，跟設定選單的「閃爍效果」是同一個值。
- **開著時**：標題選單不收鍵盤，同一下 Enter 不會順便按到「新遊戲」；面板後面標題的 CRT 閃爍也先不播，選了「保留」才播。

- **存檔**：旗標放在設定（`SettingsState`），存檔版本不升。
  - 新遊戲只清進度、不清設定，所以不會再問。

### 4.21 兩個分頁同時開遊戲

存檔只有一槽，放在同網域分頁共用的 localStorage。以前兩個分頁都開著遊戲時，persist 每次 `set` 都整份寫檔，舊分頁隨便一次寫入（改設定、存位置、補寫遊玩時間）就把另一個分頁的進度整份蓋回舊的（審計 G3）。現在的規則是「記憶體裡的進度過期的分頁停止存檔」：通常是後開的分頁先寫，所以先開的那個停。實作在 `src/game/store/gameStore.ts` 的 `safeLocalStorage` 與 `writeImportedSave`，提示是 `saveStatus.ts` 的 `other-tab`。

- **比對基準**：每個分頁記住自己最後一次讀到或寫入的存檔原始字串。讀檔前沒有基準，什麼都不判定。
- **兩條偵測路徑**：
  - **storage 事件**：別的分頁寫入或刪除存檔時，瀏覽器會通知同網域的其他分頁（自己寫的不會通知自己）。存檔 key 的新內容跟基準不一樣就判定；別的分頁刪掉存檔、清空整個 localStorage 也算。升級前的備份（`kepler9-save.backup.v*`）與其他 key 不算；新內容跟基準一模一樣不算（蓋回去也不會掉進度）；還沒讀過存檔的分頁不理會，等一下讀檔就會讀到最新的。
  - **寫入前比對**：每次寫檔前再讀一次 localStorage，跟基準不一樣也判定，補上 storage 事件沒送到的情況（分頁被凍結、從上一頁快取還原）。讀檔後的第一次寫入就會比對。存檔不見了（null）不算：沒有別人的新進度要保護，照寫反而把記憶體裡的進度存回去；別的分頁真的刪了存檔，由 storage 事件那條判定。
- **判定之後**：這個分頁之後的寫入與刪除一律略過（不丟錯、不覆蓋），記憶體照常運作，可以繼續玩，只是不存檔。畫面頂端提示「另一個分頁改了存檔，這個分頁已停止存檔。重新載入可以接續最新進度。」，文字後面接一個「重新載入」按鈕（整頁重新載入，讀到最新的存檔）。
  - 跟 4.7「存檔容錯」的提示是同一條（`SaveStatusNotice`，掛在根佈局，標題與 `/play` 都看得到）：整條不擋地圖的點擊，只有按鈕接得到滑鼠；按鈕接在文字同一行，768 寬折成兩行時底部約 164 px，仍在音效提示（top-44，176 px）上面。
  - 蓋過「存檔失敗」與「較新版本」的提示，重新載入會重新判斷；整個儲存空間不能用（`unavailable`）時讀不到基準，不會判定。
  - 這個狀態不存檔：重新載入（重新讀檔）就歸零。
- **自己的寫入不誤判**：同一個分頁寫檔不會收到 storage 事件，寫完基準跟著更新。存檔匯入（4.7「存檔管理」）寫進 localStorage 時記成這個分頁自己的寫入、不提示；但記憶體裡還是匯入前的進度，到重新載入之前不再寫檔，免得把剛匯入的存檔蓋回去。
- **匯出**：已經判定的分頁匯出 localStorage 裡最新的存檔（跟「較新版本」時一樣），不拿記憶體裡過期的進度頂替。
- **練習模式**：沙盒只讀設定、不寫檔，不會走到寫入前比對，`/sandbox` 也不顯示提示；但沙盒分頁一樣聽 storage 事件，別的分頁改了存檔後回到標題就看得到提示（那時標題的「繼續」與副標已經是舊的，按下去玩就會蓋掉別人的進度）。
- **為什麼不做**：
  - 「後開的分頁一打開就叫舊分頁停」：只是開標題看設定、進練習模式，也會讓正在玩的分頁停止存檔。改成真的有衝突才停。
  - 收到通知就自動重新讀檔、不提示：`/play` 的 Phaser 場景、終端機 Shell、NOVA 佇列都是讀檔時建好的，中途換掉存檔要整頁重建，跟換章一樣走重新載入最乾淨。
- **已知限制**：
  - 兩個分頁都停在 `/play` 而且都在前景（例如並排兩個視窗）時，遊玩時間各自每 30 秒寫一次，誰先寫誰贏；輸的那個重新載入後，如果對方又搶先寫，會再停一次。關掉不玩的那個就好。
  - 同一個分頁裡的多個 iframe、不同瀏覽器、一般視窗與無痕視窗（localStorage 不共用）不在範圍。Safari 私密瀏覽的分頁之間可能不共用儲存空間（各玩各的，不會互蓋也不會提示），舊版甚至寫不進去（走 4.7 的「存檔失敗」）。
  - 判定靠原始字串比對：別的分頁寫進跟這個分頁最後讀寫一模一樣的內容不算改了存檔。

### 6.2 自產與補充的素材

- 角色 sprite sheet：CC0 來源找不到合用的。OpenGameArt 的「Top Down Astronaut - Animated」是 Blender 3D 專案檔不是現成 sprite。改用 codex 試產，結果可用：4x4 格、四方向順序正確（下、左、右、上）、每列四幀走路循環、深藍連身服橘色反光條。AI 畫的每格位置不完全一致，用 `pnpm sprites:slice`（`scripts/slice-sprites.mjs`，需要 sharp）重切：清掉半透明雜訊、每格只留最大連通區塊、每列各自縮放、腳底對齊同一基準線。正式檔在 `public/sprites/technician-{a,c,d,e}.png`，規格如下：
  - 格子 32x48，4 欄 4 列，整張 128x192。
  - 列順序由上到下：面向下、面向左、面向右、面向上。
  - 每列四幀：站立、左腳前、站立、右腳前。走路動畫播 0-1-2-3 循環，站立用第 0 幀。
  - 角色高約 46 px，寬 20 到 28 px，腳底在格子第 47 列。
  - 選 32x48 而不是 32x32 的原因：角色圖是瘦長的，32x32 只剩 18 px 寬會糊掉；32x48 是一格 tile 寬、一格半高，跟 32px tile 的搭配是 RPG Maker XP 的經典比例。
- 音效：Kenney「Sci-fi Sounds」與「Interface Sounds」（CC0）。第一版已採用 4.10 的五種，檔案在 `public/audio/`。

### 6.3 codex 產圖流程

實測可行，一張約一到兩分鐘。場景插圖輸出大多約 1672x941（16:9），第十場改用 640x360 縮圖當風格參考時，有些只輸出 640x360（遊戲本來就用這個尺寸，見 notes/worklog.md 第十場）；NOVA 立繪是 1254x1254 PNG。提示詞從 stdin 餵、選項用 `--` 結束（`-i <FILE>...` 是可變數量參數，提示詞直接接在後面會被吃成圖片路徑，見 notes/pitfalls.md）：

```bash
cd docs/assets-draft/scenes && codex exec --skip-git-repo-check -s workspace-write -i scene-cryo-original.png -- <<PROMPT
請用你的 image_generation 工具產生一張圖：<固定風格前綴> <描述> 產生後把圖片存成目前目錄下的 scene-<name>-original.png
PROMPT
```

- codex 會先存到 `~/.codex/generated_images/<session>/`，再複製到指定路徑。
- 固定風格前綴確保幾十張圖看起來是同一個世界，例如「16-bit 像素風、深色廢棄太空站、冷藍色調、CRT 掃描線質感」。
- 不用它產 tileset 與 sprite sheet，格線對不齊。
- 實際產出：NOVA 立繪 2 張（`nova-eye`、`nova-core`）、角色 sprite 4 張、場景插圖 44 張。第一章 8 張（六個艙區、開場與結尾過場）由 `docs/assets-draft/scenes/generate.sh` 批次產生，第二到六章 36 張（每章六個艙區加結尾過場，外加片尾）由 `generate-ch2-6.sh` 產生。原圖用 `node scripts/resize-scenes.mjs` 縮成 `public/scenes/` 的 640x360 WebP 與 `docs/assets-draft/scenes/` 的 256x144 PNG 預覽。
- 冷凍艙先產當風格基準，其餘用 `-i` 附它當參考圖，風格才會一致。
- 草稿圖放在 `docs/assets-draft/`，定稿後才搬到 `public/`。
- 命名規則：原始大圖加 `-original` 後綴，例如 `nova-eye-original.png`、`scenes/scene-cryo-original.png`，已在 .gitignore 忽略；縮小後的預覽圖不加後綴，例如 `nova-eye.png`（256px）、`technician-c.png`（128px）、`scenes/scene-cryo.png`（256x144），會進版控。`.psd`、`.blend`、`.aseprite` 這類美術原始檔一律不進版控。
