- **描述**：tokenizer 只認得 |、>、>>，其他運算子都被當成一般參數。我用 Vitest 對 Shell 實測：`echo hi; echo there` 印出「hi; echo there」而且不算錯；`cd docs && ls` 只執行了 cd，ls 被丟掉（cd 只取 args[0]），也沒報錯；`ls || echo no` 跑出管線 `|` 的教學錯誤；`echo ~` 印 `~`；`echo $(pwd)` 原樣印出；`cat < a.txt`、`cd -`、`2>&1` 都回「這個目錄下沒有 `<`／`-`／`2`」。對主打「指令教學永遠正確」的遊戲來說，看過網路教學或用過 shell 的玩家會打這些寫法，結果被默默帶歪。建議在 tokenizer 偵測引號外的 ;、&&、||、&、<、2>、$(、反引號，回一則明確的 ParseError（例如「這台終端機不支援 &&，請分兩行輸入」）；開頭的 ~ 照 bash 展開；cd 參數超過一個就報錯。另外加一組 node 環境的差異測試，用同一份快照在暫存目錄建出真檔案，跟真 bash 比對 stdout，守住 README 的承諾。
- **證據**：src/game/shell/parser/tokenizer.ts:5 與 222-240（只 push pipe、redirect、redirectAppend 三種運算子）；src/game/shell/commands/cd.ts:17-18（只取 args[0]，多的參數默默丟掉）；README.md:55「行為對照 GNU coreutils / bash」；docs/game-design.md:71 只列了支援的語法，沒定義不支援時怎麼回應；實測輸出：`echo hi; echo there` → `hi; echo there`（isError false）、`cd docs && ls` → 無輸出、pwd 變成 /home/tech/docs
- **驗證**：（補漏 agent 提出，未經懷疑者驗證）
